## 1. 大浜サイトの前提値

- `.container` の左右パディング＝**24px ×2 = 48px**（えことばは22px×2なので数値が違う）
- 設計基準幅＝**360px**（現行スマホの最小幅）
- 半角英数字は約0.5文字で数える（`5,500` は5文字でなく約2.5文字分）

```
1行に収まる文字数 =（要素の内幅px）÷（フォントサイズpx + 字間px）  ※小数切り捨て
安全上限 = 収まる文字数 − 1
```

## 3. 運用ルール

1. **安全上限を超える文は `<br class="sp-br">` で行を確定させる**（自動折り返しに任せない）
   - `.sp-br` はスマホでのみ改行、PCでは無視される（style.css で定義）
   - PCだけで改行したいときは `<br class="pc-br">`
2. 改行位置は必ず**文節の切れ目**（読点のあと・助詞のあと）に置く
3. 行末に「。」「、」が来る行は1字余裕を見る（禁則処理で前の文字ごと落ちるため）
4. 金額など**分断されると困る短い塊は `white-space: nowrap`**（例：`.price-amount`）
5. 収まらない場合の優先順位＝**①改行を入れる → ②周りの余白・アイコンを詰める → ③フォントを下げる**。文言は変えない

### 併せて直したレイアウト不具合

| 症状 | 原因 | 対処 |
|---|---|---|
| トップのコラムカード見出しが5字ずつ折返し | サムネ140pxでタイトル欄が74pxしか残らない | SPでサムネ96pxへ |

### 意図的に対象外にしたもの

- **ブログ記事の本文段落**：長文なので自動折返しに任せる。ここに改行を入れると別の幅で不自然になる（基準表の対象は見出し・キャッチ・短文）
- **320px（旧iPhone SE）**：基準は360pxのまま

### 検出の注意点

- `-webkit-line-clamp` で省略されている要素は**見えない行まで検出してしまう**ので除外すること（関連記事カードがこれに該当した）
- フォントサイズが混在する行（例：`5,500` ＋ `<small>円〜</small>`）は、ベースラインがずれるため**別の行として誤検出**される。`white-space: nowrap` を当てたうえで目視確認する
