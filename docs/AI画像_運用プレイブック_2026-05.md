## A. ② GPT-Image-2（ローカル nanobanana）実運用

### A-1. ヘルパーの実仕様（generate.py を読んで確定）

呼び出し：`python "C:\Users\marak\.claude\skills\nanobanana-image-gen\scripts\generate.py" [flags]`

| フラグ | 値 | 既定 | メモ |
|--------|----|------|------|
| `--prompt` | 文字列（必須） | — | 本文 |
| `--model` | gpt-image-2 / gpt-image-1-mini / **gemini-3.1-flash** / gemini-flash / imagen4 | gpt-image-2 | gemini-3.1-flash＝Nano Banana 2 |
| `--aspect-ratio` | 1:1 / **16:9** / 9:16 / 4:3 | 1:1 | バナーは16:9 |
| `--n` | 1〜4 | 1 | 案出しは4 |
| `--quality` | low / medium / high | high | 基本highで可 |
| `--image-size` | 1K / 2K / **4K** | 1K | バナー本番は2K〜4K |
| `--filename` | 名前（拡張子任意） | 自動 | `gpt_YYYYMMDD_HHMMSS.png` |
| `--save-dir` | 絶対パス | `作業フォルダ/99_image_output` | 後述の保存先運用参照 |
| `--image` | 参照画像パス（複数可） | — | 指定で**編集モード** |
| `--from-clipboard` | — | — | Win+Shift+S直後の画像を参照 |
| `--url` | URL | — | ヘッドレスで自動キャプチャ（既定1440×2400）→編集モード |

- サーバー（localhost:5050）は未起動なら自動起動。APIキーは `29_Nanobanana_操作/.env`（GEMINI・OPENAI両方設定済）。
- stdout は JSON のみ。`saved_paths` に絶対パス。`error` キーがあれば失敗。
- **imagen4 は参照画像編集に未対応**（`--image/--url/--from-clipboard` と併用不可）。

### A-1.5. 実地検証メモ（2026-05-29 テスト生成で判明）
- ✅ **A-3プリセットはほぼ無修正で通用**。梅雨バナーを `gemini-3.1-flash / 16:9 / 2K` で生成 → 生成りベージュ・自然光・余白・低彩度の和モダンが一発で出た。日本語キャッチ「梅雨こそ、畳のお手入れを。」も**誤字なく明朝・金系で完璧に描画**。
- ⚠️ **`gemini-3.1-flash` は `--n` を無視して1枚しか返さない**。複数案が欲しいときは **(a) コマンドを複数回叩く** か **(b) `gpt-image-2` を使う**（gpt系は `--n` が効く）。
- `model_used` は `gemini-3.1-flash-image-preview` と返る（正常）。
- オリーブ #556B2F は自然光の緑に溶けて主張は弱め。畳縁や器で差し色を効かせたいときはプロンプトに明示追加するとよい。

#### gpt-image-2 との比較検証（2026-05-29 追試）
- ✅ **新規パーツ作成のデフォルトは gpt-image-2 が総合上**。同じ梅雨バナーで比較 → gemini同等以上の品質に加え、**金アクセント・床の間など"ブランドの作り込み"が濃く**、テキストも完璧、`--n 2` で複数案も出る（gemini は1枚固定）。
- ✅ **用途別プリセットも即戦力**：い草質感カット・コラムサムネ（急須湯呑＋床の間）はほぼ手直し不要の品質で出た。
- ✅ **`--url` リデザイン（gpt-image-2）が実サイトで機能**：goods.html を渡すと**商品名・価格・メニュー・電話/LINE・グリッド構成を保持**したまま和紙トーンで上品に再構成。
- ⚠️ **リデザイン検証はセクション単位で**：9:16でページ全体を出すと本文テキストが小さく潰れる。**ページ全体より、セクション単位でキャプチャ**した方が文字も読めて実装に使える。
- ⚠️ **`--url` 実行時に `UnicodeDecodeError`(cp932) がstderrに出るが無害**。`saved_paths` が返れば生成は成功している。
- 使い分け確定：**新規でキッチリ作り込む＝gpt-image-2 ／ 元画像を忠実に保って直す＝gemini-3.1-flash**。

## C. ③ Claude Design 実運用

### C-0. アクセス方法・私（Claude Code）との連携（2026-05-29 調査）
- **どこにある**：**claude.ai のWebアプリ**（左サイドバーの「パレット」アイコン）。デスクトップアプリではなくWeb。Pro/Max/Team/Enterprise で利用可（新垣さんはMax＝利用可）。
- **公開APIはない**：CLI・プログラムからの直接呼び出し不可。**私が単独でClaude Designを操作することはできない**＝新垣さんがブラウザで操作する前提。
- **入力（読ませ方）**：ライブ接続ではなく**ファイルアップロード／コードベース取り込み**。GitHub・ローカルのコードベース、style.css、スクショ、フォント・ロゴ、スタイルガイドを渡すと、色・フォント・コンポーネントを抽出して自動適用。
- **出力（受け渡し）**：HTML / ZIP / PDF / PPTX / **Canvaへ送る** / 共有リンク / **★Claude Code への handoff**。Figmaへの直接書き出しは不可。
- **🔑 私との連携線**：①私が **style.css＋ブランドブリーフ＋対象HTML を整えてClaude Designに渡せる形に用意** → ②新垣さんがClaude Designで反復 → ③**「Claude Codeへ handoff」or HTML書き出し** → ④私が本番の静的HTMLに実装。（Canva書き出しはこの環境のCanva MCPで後工程に使える）
- 補足：静的HTMLサイトなら、**私が直接デザイン→コード実装する**道もある。Claude Designは「先に見た目を確定させたい時の高速プロト」用途。

### C-1. 基本ワークフロー

### C-2. 強み／弱み（実務で意識）

- **トークン大食い → 本案件は無制限なので遠慮なく反復してよい**（最大の弱点が無効化）。
